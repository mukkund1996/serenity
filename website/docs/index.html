Getting around serenity

serenity puts every Claude Code session on one keyboard-driven map in your terminal, around a master agent that keeps the overview. This page covers what you need on day one.

Install

macOS or Linux. One command installs serenity and anything it needs that you don't have yet: tmux 3.2+, git, gh and Claude Code.

$ curl -fsSL https://raw.githubusercontent.com/mukkund1996/serenity/main/scripts/install.sh | sh

Or with Homebrew (tmux, git and gh come as dependencies; Claude Code is a cask):

$ brew install --cask claude-code; brew install mukkund1996/tap/serenity

The install script reads these environment variables:

VARIABLEDEFAULTEFFECT
SERENITY_VERSIONlatest releaseInstall a specific version
SERENITY_INSTALL_DIR~/.local/binWhere the binary goes
SERENITY_NO_DEPSunsetSet to 1 to skip installing dependencies

serenity runs on your existing Claude Code login and subscription.

Starting serenity

serenity is scoped to a repo: run it inside one and you get that repo's map.

$ gh auth login   # optional: PR status on cards
$ cd ~/your/repo
$ serenity        # opens the map for this repo

Press N to start your first session and ? for the shortcuts. q quits the map; your sessions keep running, and the next serenity picks them up again.

COMMANDWHAT IT DOES
serenityOpen the map for the git repo you are in
serenity doctorCheck tmux, claude, git and gh
serenity slack loginSign in to Slack for the master (once)
serenity restartRestart the background daemon (sessions keep running)
serenity stopStop the background daemon
serenity versionPrint the version

Behind the map, a background daemon keeps the state, receives status from Claude Code hooks, polls PRs through gh and runs the master. If it crashes, a supervisor restarts it and it picks up where it left off.

The map

serenity has three zoom levels:

  • Map: the master in the centre, your sessions grouped into topic bubbles around it.
  • Topics: every session as a card, with its summary and its PR.
  • Session: the real Claude Code pane, untouched.

z zooms out to the map, Z zooms in to the topics, and Esc goes up one level. Move with the arrow keys or WASD; [ ] step between topics, c centres on the master and / searches session names, topics and branches as you type.

The master picks the topics for you and keeps them to a handful (ten by default). Each session shows its status, reported by Claude Code's hooks:

GLYPHMEANS
◐ yellowWaiting on you. Only these ask for attention.
● blueWorking. It stays quiet.
✓ greenFinished.
name in greyIdle.

Sessions

Each session is a real claude process in its own tmux pane, usually in its own git worktree.

Start one

N opens the New session form: a name, a first prompt, and either a new worktree or an existing branch. A new worktree is created beside the repo, at <parent>/<repo>-<name>, on a new branch named after the session off the default branch. You can also ask the master to start sessions for you (see @new).

I imports Claude sessions you already run in tmux. They join the map and stay in their windows.

Work in one

Enter on a card attaches to the session: you are in its Claude Code pane, as it is. Ctrl+g takes you back to the map. To send a quick message without attaching, press i on its card.

Pull requests

Each card shows its PR and checks via gh. o opens the PR. Ready PRs get a review request from CODEOWNERS, and a merged PR finishes the session.

Keep, rename, end

  • p pins a session you reuse. It is never marked finished or cleaned up, and resumes with claude --resume when you attach after it ended.
  • f watches a session; r renames it.
  • K kills the agent. x cleans the session up, after checking for uncommitted changes, unpushed commits and PR state before it touches the worktree.
  • H shows archived sessions.

NEEDS YOU

NEEDS YOU is the one list of what is waiting on you, and the yellow N need you chip at the top counts it. It holds sessions waiting on an answer or a permission prompt, the master's suggestions, and, if you set up Slack, up to three mentions and DMs that need you to act.

Each item carries a ◆ line that says exactly what y will do and to whom, for example Tell api-auth: …, Reply in #eng thread: … or Start new session fix-login: ….

KEYON A NEEDS YOU ITEM
TabJump to the next session that needs you
y e nRun the ◆ suggestion · edit it · decline it
EnterMark it seen. A Slack item is also opened in Slack; a session waiting on a prompt or a question is attached instead
xDismiss a Slack item

Replies the master wants to send to a session wait in their own QUEUE under NEEDS YOU, so they never make an idle session look like it needs you. Enter shows the whole message, y sends it.

Slack is optional. Run serenity slack login once and list the repo under slack.repos in ~/.config/serenity/config.json. A Slack item drops out as soon as you write after it on Slack.

The master agent

The master sits in the centre of the map and keeps the overview, using three models through your Claude Code login:

  • Haiku writes a one-line summary of every session and groups them into topics.
  • Sonnet suggests replies, approvals and cleanups, which you accept with y, edit with e or decline with n.
  • Opus is the chat: it can see and steer every session, start new ones from a brief, and talk to any session you tag.

The master proposes; nothing runs until you approve it. The exceptions are the ones you ask for in so many words: starting sessions from a brief, and messaging a session you @-mention.

Talking to it

Ctrl+m focuses the master from anywhere (in Apple Terminal, Enter). i on the master opens its chat input, which stays open after you send. Shift+Enter or Ctrl+J starts a new line, Esc closes it, and PgUp PgDn scroll the conversation.

@ mentions

In the master's input, @ opens a list that completes as you type: the commands first, each with a hint, then the live sessions of the repo. ↑ ↓ move, Tab or Enter complete, Esc closes the list. Names are exact and case-sensitive, which is why the list completes whole names.

@session: talk to a session

A message that tags a session goes to that session at once, lightly reworded to stand on its own. The master doesn't investigate it itself: the session's own agent does the looking. If you asked a question, the master watches the session and condenses its answer for you when it replies.

@api-auth why is CI red?
◈ Asked api-auth; I'll relay its answer.

@new <brief>: start sessions now

Starts the work at once, with no plan to confirm: one session, or one per piece when the brief clearly holds independent pieces. The master picks the names, topics and prompts. A split you don't want costs a K on the extra sessions.

@new add rate limiting to the public API and document it

@copy @session <follow-up>: continue in a fresh session

The session writes a handover doc (goal, state, decisions, open questions, key files, branches and PRs, next steps). serenity keeps a copy that outlives the worktree, then the master starts a new session with your follow-up and the doc attached word for word.

@copy @api-auth add the refresh-token flow next

@handover @session: write it down for someone

Gets a handover doc from the session, or reuses an up-to-date one, and gives you its path. The master can share it on Slack as a file, once you have confirmed the file, the channel and the comment.

@handover @api-auth

Command words such as new are reserved: no session can take them as its name.

Key bindings

serenity is keyboard-only. The footer shows the moves; ? opens the shortcuts in the app.

KEYACTION
←↑↓→ / WASDMove between nodes
EnterAttach to a session, or go into the master; on a NEEDS YOU item, mark it seen
iSend the focused session a quick message; on the master, open its chat input
Ctrl+gBack to the map from inside a session
z Z EscZoom out to the map · zoom in · one level up
Ctrl+mFocus the master from anywhere (Enter in Apple Terminal)
PgUp PgDnOn the master, scroll its conversation (Shift+↑ ↓ too)
TabJump to the next session that needs you
y e nApprove, edit or decline the master's suggestion
[ ]Previous / next topic
N INew session · import from tmux
o f pOpen the PR · watch · pin
r K xRename · kill the agent · clean up; on a Slack item, x dismisses it
/ c HSearch sessions · centre on the master · archived sessions
? qShortcuts · quit the map (sessions keep running)

In a text field

← → Home End move the cursor, Option+← → by a word. Ctrl+a e w u k and Option+Backspace edit as in a shell.
